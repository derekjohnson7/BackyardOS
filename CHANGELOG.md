## v0.7.0 — Reliable Telemetry (COMPLETE)

### Added
- Added automatic Wi-Fi reconnection behavior.
- Added retry handling for failed telemetry POST requests.
- Added API key authentication for sensor write requests using the `X-API-Key` header.
- Added HTTPS certificate validation using the GTS Root R4 trust anchor.
- Standardized sensor timestamps to UTC.
- Reduced telemetry frequency to a 10-minute interval for long-term monitoring.

### Improved
- Sensor telemetry now retries failed POST requests up to three times before giving up.
- Wi-Fi connectivity is checked before telemetry transmission and automatically restored when possible.
- NTP synchronization is requested again after Wi-Fi reconnection.
- Sensor write requests are rejected unless a valid API key is supplied.
- HTTPS connections now validate the backend certificate chain instead of using insecure TLS mode.

### Verified
- ESP32 successfully reconnects after Wi-Fi loss.
- Failed HTTPS requests are retried automatically.
- Authenticated telemetry returns `200 OK`.
- Requests without the required API key are rejected.
- UTC timestamps are generated by the ESP32.
- HTTPS certificate validation successfully connects to the hosted Render backend.
- Sensor readings continue to persist successfully in PostgreSQL.
- End-to-end reliable telemetry pipeline verified:

  `Sensors -> ESP32 -> Wi-Fi -> HTTPS/TLS -> API Key Auth -> FastAPI -> PostgreSQL`

### Notes
- Telemetry interval is currently 10 minutes.
- UTC is used for stored sensor timestamps to provide a consistent time standard across future dashboards and analytics.
- The FastAPI/PostgreSQL response currently serializes timestamps without an explicit timezone suffix, although the ESP32 generates and transmits UTC time.
- The ESP32 trusts the GTS Root R4 certificate authority for HTTPS validation.
- The root certificate may need to be updated in the future if the hosted backend changes certificate authorities.
